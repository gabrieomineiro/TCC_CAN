-Estou querendo fazer um controlador CAN em verilog/systemverilog que funcionaria como módulo responsável pela comunicação de um módulo mais complexo que inclui o controlador. Até agora tenho um módulo reponsavel pelo bit timing unit. Liste que módulos são necessários para a comunicação completa

--Para implementar um **controlador CAN** completo em Verilog/SystemVerilog (compatível com a especificação CAN 2.0A/B ou CAN FD), você precisará dos seguintes módulos, além da **Bit Timing Unit (BTU)** que você já possui:

---

## **Módulos essenciais para o controlador CAN**

### 1. **Bit Stream Processor (BSP)**  
- **Função:** Gerencia a serialização/deserialização dos bits no barramento CAN (RX/TX).  
- **Responsabilidades:**  
  - Monitora o bit de dominante/recessivo no RX.  
  - Gera o bit TX com base no estado da máquina de estados.  
  - Implementa **NRZ (Non-Return to Zero)** com **bit stuffing** (5 bits iguais → bit oposto).  

### 2. **CRC Unit (Cyclic Redundancy Check)**  
- **Função:** Calcula e verifica o CRC de 15 bits (CAN 2.0) ou 17/21 bits (CAN FD).  
- **Responsabilidades:**  
  - Gera CRC na transmissão.  
  - Compara CRC recebido com o calculado na recepção.  
  - Gera erro se houver divergência.

### 3. **Error Management Logic (EML)**  
- **Função:** Implementa a **contagem de erros** (Transmit Error Counter – TEC, Receive Error Counter – REC).  
- **Responsabilidades:**  
  - Incrementa/decrementa contadores conforme erros detectados.  
  - Controla os estados do nó: **Error Active**, **Error Passive**, **Bus Off**.  
  - Gera flag de erro (error frame) quando necessário.

### 4. **Message Handler / Acceptance Filter**  
- **Função:** Filtra mensagens recebidas com base no ID e máscara de aceitação.  
- **Responsabilidades:**  
  - Compara ID da mensagem com filtros configurados.  
  - Rejeita mensagens não desejadas antes do armazenamento.  
  - Suporte a **IDs padrão (11 bits)** e **estendido (29 bits)**.

### 5. **Transmit Buffer & Receive Buffer (FIFO)**  
- **Função:** Armazenamento temporário de mensagens.  
- **Responsabilidades:**  
  - **Tx Buffer:** Armazena mensagens prontas para transmissão (arbitragem).  
  - **Rx FIFO:** Armazena mensagens recebidas e aprovadas no filtro.  
  - Controle de overflow.

### 6. **Arbitration Logic**  
- **Função:** Implementa a arbitragem **CSMA/CD with BA** (bitwise arbitration no ID).  
- **Responsabilidades:**  
  - Compara bit a bit o ID transmitido com o que está no barramento.  
  - Se perder arbitragem: para de transmitir e passa a receber.  
  - Detecta bit dominante quando transmitiu recessivo → perdeu.

### 7. **Frame Sequencer / Protocol Controller FSM**  
- **Função:** Máquina de estados principal que implementa o **formato do frame CAN**:  
  - **SOF** (Start of Frame)  
  - **Arbitration Field** (ID + RTR/SRR/IDE)  
  - **Control Field** (DLC)  
  - **Data Field** (0-8 bytes ou mais no CAN FD)  
  - **CRC Field** + Delimiter  
  - **ACK Field** (Slot + Delimiter)  
  - **EOF** (End of Frame)  
  - **Intermission**  
- **Responsabilidades:** Controla a sequência correta de transmissão/recepção.

### 8. **Interrupt Controller / Status Register**  
- **Função:** Comunicação com o host (módulo mais complexo que você mencionou).  
- **Responsabilidades:**  
  - Gera interrupções para: Rx disponível, Tx concluído, erro, Bus Off, etc.  
  - Mantém registradores de status (transmitindo, recebendo, error state).  
  - Interface com bus de sistema (APB, AXI, Wishbone, etc.).

### 9. **Clock Domain Crossing (CDC) Unit** (se necessário)  
- **Função:** Se o seu controlador CAN opera em domínio de clock diferente do módulo host ou do bit timing (ex: 8 MHz para CAN, 50 MHz para sistema).  
- **Responsabilidades:** Sincronização de sinais de controle e dados entre domínios.

---

## **Conexão típica com BTU (Bit Timing Unit)**

A BTU que você já possui deve fornecer sinais como:  
- `sample_point` – momento de amostragem do RX.  
- `tq_clk` – clock por time quantum (para sincronização de borda).  
- `sync_edge_detected` – para reinicialização de temporizadores (hard/soft sync).  

Esses sinais alimentam o **Bit Stream Processor** e o **Protocol FSM**.

# 📋 Roteiro de Desenvolvimento – Controlador CAN 2.0B

**Cliente:** Módulo complexo (sistema embarcado proprietário)  
**Tecnologia:** Verilog / SystemVerilog  
**Alvo:** FPGA ou ASIC  
**Entrega:** RTL sintetizável + testbench + documentação

## 🔹 FASE 0 – ESPECIFICAÇÃO E PLANEJAMENTO (2 semanas)

### Atividades
- Levantamento da especificação CAN 2.0B (ISO 11898-1)
- Definição da interface com o módulo host:
  - Largura do barramento de sistema (8/16/32 bits)
  - Tipo de interface (APB, AXI-lite, Wishbone ou simples handshake)
  - Pinos: `clk`, `rst_n`, `can_rx`, `can_tx`, `irq`, `addr[2:0]`, `data[7:0]`, `wr`, `rd`, `cs`
- Definição das características:
  - Apenas **BasicCAN** ou **FullCAN**?
  - Suporte a **IDs estendidos (29 bits)**?
  - Número de buffers de transmissão/recepção (ex: 1 Tx, 2 Rx FIFO)
  - Filtros de aceitação (ex: 4 filtros configuráveis)

### Entregáveis
- Documento de arquitetura do controlador
- Diagrama de blocos
- Cronograma de entregas parciais

## 🔹 FASE 1 – MÓDULOS FUNDACIONAIS (3 semanas)

### Semana 1 – Bit Timing Unit (já existente)
- Verificar se sua BTU cobre:
  - Divisor de clock para **Time Quanta (TQ)**
  - **Synchronization Jump Width (SJW)**
  - **Phase Segments (TSEG1, TSEG2)**
  - Amostragem em `sample_point`
  - Detecção de borda para **resincronização**
- **Testbench:** simulação com diferentes taxas (125k, 250k, 500k, 1M bps)

### Semana 2 – Bit Stream Processor (BSP)
```systemverilog
module bsp (
  input  logic clk, rst_n,
  input  logic can_rx,
  output logic can_tx,
  input  logic sample_point,      // da BTU
  input  logic [7:0] tx_data,
  output logic [7:0] rx_data,
  input  logic tx_start,
  output logic rx_done, tx_done,
  output logic bit_stuff_error,
  input  logic stuff_enable        // habilita/desabilita stuffing
);
```
- Implementar:
  - Serializador (TX)
  - Deserializador (RX)
  - Bit stuffing (5 bits iguais → insere bit complementar)
  - Destuffing
- **Testbench:** loopback interno com padrões de estouro de stuffing

### Semana 3 – CRC Unit (15 bits CAN 2.0)
- Polinômio: `x^15 + x^14 + x^10 + x^8 + x^7 + x^4 + x^3 + 1`
- Implementar LFSR paralelo (um clock por bit)
- Sinais:
  - `crc_reset`, `crc_enable`, `crc_in_bit`, `crc_out[14:0]`, `crc_match`

---

## 🔹 FASE 2 – MÁQUINA DE PROTOCOLO (4 semanas)

### Semana 4 – Frame Sequencer FSM
```systemverilog
typedef enum logic [4:0] {
  IDLE, SOF, ARB_ID, ARB_EXT, CTRL, DATA, 
  CRC, CRC_DEL, ACK_SLOT, ACK_DEL, EOF, 
  INTERMISSION, OVERLOAD, ERROR_FLAG
} can_state_t;
```
- Implementar sequência de **transmissão** e **recepção**
- Controlar CRC enable/disable por campo do frame
- Controlar bit stuffing ativo apenas entre SOF e CRC (excluindo CRC delimitador, ACK, EOF)

### Semana 5 – Arbitration Logic
- Comparar bit TX com bit RX durante campo de arbitração
- Implementar perda de arbitragem:
  - Se enviou recessivo (`1`) e leu dominante (`0`) → perdeu
  - Passar para modo receptor imediatamente
- Detectar **bus idle** (11 bits recessivos consecutivos)

### Semana 6 – Error Management Logic
```systemverilog
module error_handler (
  input  logic [7:0] tec, rec,           // contadores de erro
  input  logic error_type,                // bit, stuff, crc, form, ack
  output logic error_passive, bus_off,
  output logic error_flag_out
);
```
- Incrementar TEC em erros de transmissão
- Incrementar REC em erros de recepção
- Implementar **Error Active** (TEC<128 e REC<128)
- **Error Passive** (TEC≥128 ou REC≥128)
- **Bus Off** (TEC≥256) → só recupera após 128x11 bits recessivos

### Semana 7 – Teste integrado BTU+BSP+CRC+FSM+Arbitration+Error
- Simulação com 2 instâncias do controlador em loopback externo
- Forçar erros: CRC errado, ACK perdido, bit stuffing inválido, erro de forma (form error)

---

## 🔹 FASE 3 – BUFFERS, FILTROS E INTERFACE (3 semanas)

### Semana 8 – Acceptance Filter
```systemverilog
module acceptance_filter (
  input  logic [10:0] can_id_11b,   // ou [28:0] extended
  input  logic [10:0] mask, code,
  output logic accept
);
```
- Suporte a **4 filtros independentes**
- Modo **lista branca** (accept if match) ou **lista negra**

### Semana 9 – Tx/Rx FIFO + Message Handler
- **Tx Buffer:** 1 mensagem (mínimo) ou FIFO com 3 mensagens
- **Rx FIFO:** profundidade 4 a 8 mensagens
- Cada mensagem armazena: ID (11/29b), DLC (4b), data (0-8 bytes), RTR, IDE
- Sinais de controle: `tx_push`, `rx_pop`, `fifo_full`, `fifo_empty`, `rx_msg_ready`

### Semana 10 – Interface com Host e Interrupt Controller
- Registradores mapeados em memória:
  - `CAN_CON` (controle: enable, loopback, reset)
  - `CAN_STATUS` (tx_ready, rx_available, error_state, bus_off)
  - `CAN_COMMAND` (tx_request, abort, release_buffer)
  - `CAN_INT_EN` / `CAN_INT_FLAG` (interrupções)
- Gerar `irq` para: Rx disponível, Tx completo, erro, Bus Off

---

## 🔹 FASE 4 – INTEGRAÇÃO E VALIDAÇÃO (3 semanas)

### Semana 11 – Integração do topo
```systemverilog
module can_controller_top (
  input  logic clk, rst_n,
  // interface com host
  input  logic [2:0] addr,
  inout  logic [7:0] data,
  input  logic wr, rd, cs,
  output logic irq,
  // interface CAN
  input  logic can_rx,
  output logic can_tx,
  // interface com BTU (externa ou interna)
  input  logic sample_point,
  input  logic tq_clk
);
```

### Semana 12 – Simulação de validação
- **Testbench principal:** Verificação funcional completa
- **Cenários críticos:**
  - Arbitragem entre 2 nós transmitindo simultaneamente
  - Recuperação de Bus Off
  - Overflow de Rx FIFO
  - Erro de stuffing em campo de dados
  - Overload frame
  - Sleep/wake-up

### Semana 13 – Síntese e timing (FPGA/ASIC)
- Síntese com constraints de clock (ex: 50 MHz sistema, 1 MHz CAN)
- Relatório de área (LUTs/FFs no FPGA, gates no ASIC)
- Verificação de setup/hold para interface assíncrona `can_rx`
- Análise de **clock domain crossing** (se BTU tiver clock separado)

## 🔄 FLUXO DE DADOS PRINCIPAL

### **Transmissão (TX)**
```
Host → Tx FIFO → Frame Sequencer → Arbitration Logic → BSP (Serializer) → CRC → can_tx
                                                    ↑
                                              BTU (tq_clk/sample)
```

### **Recepção (RX)**
```
can_rx → BSP (Deserializer) → CRC Check → Frame Sequencer → Acceptance Filter → Rx FIFO → Host
                              ↑                 ↓
                        BTU (timing)    Error Management (TEC/REC)
```

### **interrupt_controller.sv**

```systemverilog
module interrupt_controller (
    input  logic        clk, rst_n,
    input  logic        tx_done,
    input  logic        rx_available,
    input  logic        error_occurred,
    input  logic        bus_off_event,
    input  logic [5:0]  irq_enable,
    input  logic [5:0]  irq_clear,
    output logic [5:0]  irq_flags,
    output logic        irq
);
    
    logic [5:0] flags;
    
    // Flag definitions
    localparam TX_DONE_FLAG     = 0;
    localparam RX_AVAIL_FLAG    = 1;
    localparam ERROR_FLAG       = 2;
    localparam BUS_OFF_FLAG     = 3;
    
    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            flags <= 6'b0;
        end else begin
            if (tx_done)        flags[TX_DONE_FLAG]  <= 1'b1;
            if (rx_available)   flags[RX_AVAIL_FLAG] <= 1'b1;
            if (error_occurred) flags[ERROR_FLAG]    <= 1'b1;
            if (bus_off_event)  flags[BUS_OFF_FLAG]  <= 1'b1;
            if (|irq_clear)     flags <= flags & ~irq_clear;
        end
    end
    
    assign irq_flags = flags;
    assign irq = |(flags & irq_enable);
    
endmodule
```
